SessionRepository 的四职责流向（唯一有设计量的部分）

存储动词
create / update / deleteById / updateLastActiveAt / getMeta / countAll
→ SessionFileStore 已有同名能力，调用方直改（纯机械替换）。
索引查询
findByParentId→childrenOf（已有）；countByParentId / findByBotAndExternalId / listWebSessionIds / getManyByIds / getSessionType / deleteChildrenOf
→ 补进 SessionFileStore——内存索引上的领域查询本就是 store 的正当词汇（childrenOf 已是先例）。
用例查询
findAll / findArchived（web+归档+分组+关键词过滤 + 内存分页 + total）
→ 上移 session.service 私有方法 querySessions / queryArchivedSessions——过滤器是用例知识而非存储知识。
视图水合
hydrate / hydrateMany（补 session.character，Prisma include 遗迹）
→ session.service 私有方法 hydrateSession / hydrateMany；API 形状逐字段保留，前端零改动。

计划称「被删 shim 无 spec 引用」不准确：bot-admin.dto.spec.ts 以 Nest 测试模块 provider 形式引用了 CharacterRepository改为 mock CharacterFileStore，避免删文件后 spec 断裂

session-search-sessions.spec.ts mock 了 SessionRepository 的 findAll/listWebSessionIds/getManyByIds改写为 mock SessionFileStore 的 query/get/listWebSessionIds/getManyByIds
