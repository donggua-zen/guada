# 统一订阅器重构方案(精简版)

> 状态:定稿待实施
> 日期:2026-08-23
> 背景:SSE 通道已归一为全局单通道,但前端仍保留三条链路各自订阅、多层包装,存在重复监听与过深层级。
> 目标:一个统一订阅器 + 发送中状态,删多余包装。

---

## 一、现状问题(调查确认)

### 1. 三条链路各自订阅,存在重复

| 链路 | 订阅点 | 事件 | 用途 |
|---|---|---|---|
| A | `useSessionEvents`(MainLayout 常驻) | `stream_status_changed` | 侧边栏 working、unread、队列消费 |
| B | `ChatPage`(聊天页) | `stream_status_changed` | agentTabs 状态 + 触发 `subscribeToActiveStream` |
| C | `useStreamResponse` | `streamEventHub.subscribe` | 流式内容渲染(每会话一个,必要) |

- **A 和 B 重复订阅同一事件** `stream_status_changed`,各取所需 → 应合一
- C 是每会话内容订阅(不同用途,保留一个)

### 2. 调用层级太深(历史遗留)

```
handleSendMessage → handleStreamResponseWithCreate → processStreamWithCreate
  → processStreamLoop → subscribeStreamEvents → streamEventHub.subscribe
```
`subscribeStreamEvents` → `processStreamLoop` → `processStream` 三层本质是透传包装。

打开会话侧:
```
handleSessionChange → loadSession → checkActiveStreamOnLoad(只剩一行)
  → subscribeToActiveStream → handleStreamResponseAsSubscriber → processStream
```
`checkActiveStreamOnLoad` 已是薄包装。

### 3. 发送瞬间状态窗口

发送即本地 `setSessionIsStreaming(true)`,但后端 `running` 事件到达有时间差 → 需要"发送中(pending)"状态填充。

---

## 二、目标架构:一个统一订阅器

### 2.1 状态订阅合一

**useSessionEvents(常驻)成为唯一 `stream_status_changed` 订阅器**,收到事件后:
1. 更新侧边栏 working/unread/队列(原有职责)
2. 写入 **sessionStore.streamStatus**(新字段,统一流状态)

**ChatPage 不再自己 `onSessionEvent('stream_status_changed')`**,改为 `watch` 派生:

```
ChatPage watch sessionStore 的 streamStatus / isStreaming
  → 更新 agentTabs 状态(running/completed/error)
  → 主会话 running 且非自身发起 → 触发 subscribeToActiveStream
```

### 2.2 流状态模型(含"发送中")

sessionStore 新增**统一流状态字段**(替代分散的 isStreaming + sidebar.working 各管各):

```ts
type StreamStatus =
  | "idle"        // 无流
  | "pending"     // 已发送,等待后端 running(发送中)
  | "running"     // 后端已确认流开始
  | "completed"   // 正常结束
  | "error";      // 出错/取消

// sessionStore
streamStatus: Record<sessionId, StreamStatus>
setStreamStatus(sessionId, status)
```

**状态迁移**:

```
idle ──发送──► pending ──收 stream_status_changed(running)──► running ──(completed)──► completed
                       │                                        └──(error)──► error
                       └──发送失败─────────────────────────────────────────► error
```

- **pending**:发送瞬间本地置(不等后端),UI 显示"发送中"
- **running**:后端 `stream_status_changed` running 到达
- **completed/error**:后端结束事件到达

### 2.3 删包装

- 删 `checkActiveStreamOnLoad`(只包一行)
- `handleSessionChange` 直接 `await subscribeToActiveStream(newSessionId)`
- `subscribeStreamEvents` 内部逻辑保留(它是真实订阅+消费),但可并入 `processStreamLoop` 或保留一层
  - 决策:保留 `subscribeStreamEvents` 一层(它有明确的生成器职责:订阅+取增量+触发),删 `processStream`/`processStreamLoop` 中纯透传的部分,不再叠 3 层

---

## 三、落地改动清单

### sessionStore(session.ts)
1. `SessionState` 加 `streamStatus: StreamStatus`(默认 "idle")
2. 新增 `setStreamStatus(sessionId, status)`(写 streamStatus + 同步 sidebar working 派生)
3. 保留 `setSessionIsStreaming` 兼容(内部转为 streamStatus 迁移)

### useSessionEvents(统一订阅器)
4. `stream_status_changed` 处理器:
   - 已有:侧边栏 working/unread/队列消费
   - 新增:按 status 写 `sessionStore.setStreamStatus(sessionId, status)`
   - running 且非自身发起 → 主会话触发 `subscribeToActiveStream` 的逻辑上移至此(替代 ChatPage 监听)

### ChatPage.vue
5. 删 `onSessionEvent('stream_status_changed', handleStreamStatusChanged)` + `unsubscribeStreamStatus`
6. 改为 `watch(() => sessionStore.getSessionState(sid)?.streamStatus, ...)`:更新 agentTabs + 触发订阅

### ChatPanel.vue
7. 发送流程置 `setStreamStatus(sid, "pending")`(handleSendMessage / handleStreamResponseWithCreate)
8. `subscribeStreamEvents`/`processStreamLoop` 结束时按实际结果置 completed/error(替代 setSessionIsStreaming(false))
9. 删 `checkActiveStreamOnLoad`,`handleSessionChange` 直接调 `subscribeToActiveStream`
