# 移动访问（局域网 / 公网 SSH 隧道）

移动访问让手机、平板等设备通过浏览器远程控制本机 GuaDa（对话、文件、终端等）。
入口在 **设置 → 移动访问**，以及侧边栏用户中心旁的手机图标（远程控制弹窗）。

## 安全前提（强制）

- 开启局域网或公网访问前，**必须先设置访问密码**（设置 → 安全设置）。
- 未设密码时开启会被后端拒绝；已开启时**禁止取消密码**（需先关闭移动访问）。
- 应用启动时还会兜底检查：若配置文件为开启状态但账户无密码，会自动关闭全部入口并提示。
- 外部设备通过密码登录，登录后拥有与桌面端相同的权限（包括终端与文件操作），
  请仅在可信网络/服务器上开启。

### 密码强度策略

- **所有密码**：至少 8 位，且包含「字母 / 数字 / 符号」中的至少 2 类；常见弱密码
  （如 `password123`、`12345678`）与包含用户名的密码会被拒绝。
- **公网访问开启期间**：设置或修改密码还要求至少 12 位、字母/数字/符号三类齐全。
  该强度检查只在设置/修改密码时用明文校验一次。
- 密码校验大小写不敏感，因此大写字母不额外增加强度，策略按三类字符计算。
- 不保存强度快照，也不会在开启入口或启动时对存量密码做二次判断——避免状态陈旧
  导致「改了密码仍被拦截」。旧密码是否够强由用户自行判断，公网开启后的任何密码
  修改都必须满足高强度。

## 局域网访问

1. 设置 → 移动访问 → 打开「允许局域网设备访问」。
2. **重启应用**（设置页提供「立即重启应用」按钮）——监听地址在进程启动时决定。
3. 手机连接同一个 Wi-Fi，打开设置页展示的地址，例如 `http://192.168.1.10:3000/`。

说明：

- Linux/macOS 需放行防火墙对应端口；Windows 首次监听时可能弹出防火墙授权，请允许
  （仅专用/私有网络需要）。
- **开发模式（Vite）**：局域网与公网入口都直接指向 Vite dev server 的 `5173`，
  手机端享受热重载，无需先构建前端；设置页/弹窗展示的地址就是 `http://<IP>:5173/`。
  需要 `pnpm dev` 正在运行（Vite 已配置 `host: true` 与 `allowedHosts: true`）。
- **生产模式**：由后端 serve 编译产物，入口为后端当次端口（随机），请以设置页/
  弹窗展示的地址为准。
- 前端页面由后端直接 serve（生产）或 Vite（开发）；深链接刷新在生产模式下已通过
  注入 `<base href="/">` 处理。

## 公网访问（SSH 反向隧道）

本机主动连接你自己的公网服务器，建立 `ssh -R` 反向隧道，无需公网 IP、路由器端口
转发或 DDNS。服务器只需运行 sshd。

### 服务器准备

1. 确认 sshd 允许 TCP 转发（默认 `AllowTcpForwarding yes`）。
2. 若「远端监听地址」选择 `0.0.0.0`（公网直接访问端口），sshd 需配置
   `GatewayPorts yes`（或 `clientspecified`），并在服务器防火墙/安全组放行该端口。
   若选择 `127.0.0.1`（推荐，配合服务器反代），则无需改 GatewayPorts，请在该服务器上
   用 nginx 等反向代理到 `127.0.0.1:<远端端口>`，由代理负责 HTTPS/域名。
3. 为 GuaDa 准备一个 SSH 账户，使用私钥或密码认证。

#### 为什么多数服务器默认不能公网转发？

OpenSSH 上游默认 `GatewayPorts no`，主流发行版（Debian/Ubuntu/CentOS/RHEL 等）出厂配置
也只保留注释行，所以生效值就是 `no`：`ssh -R 0.0.0.0:8787:...` 会被 sshd 拒绝或
静默退化为只绑 `127.0.0.1`。这是安全默认值，避免任意 SSH 用户把内网服务暴露到公网。

#### 快速启用（推荐 `clientspecified`）

`clientspecified` 允许客户端自己决定绑 `127.0.0.1` 还是 `0.0.0.0`，比无条件 `yes`
更可控。SSH 登录服务器后用 root（或 sudo）：

```bash
# 方式 A：直接追加到主配置（适用大多数发行版）
echo 'GatewayPorts clientspecified' >> /etc/ssh/sshd_config

# 方式 B：用 drop-in（Debian/Ubuntu、RHEL/CentOS 8+ 自带 Include，优先级更高）
printf 'GatewayPorts clientspecified\n' > /etc/ssh/sshd_config.d/10-gatewayports.conf

# 校验并重启（Ubuntu/Debian 服务名可能是 ssh）
sshd -t && systemctl restart sshd   # 或: service ssh restart
```

> sshd_config 是「首个有效值生效」：追加在文件末尾即可，注释行（`#GatewayPorts no`）
> 不参与匹配。已有 SSH 会话不会因重启 sshd 断开。

验证生效：

```bash
sshd -T | grep -i gatewayports          # 期望: gatewayports clientspecified
# 客户端重连后（应用里选 0.0.0.0）：
ss -lntp | grep 8787                    # 期望: 0.0.0.0:8787（而不是 127.0.0.1:8787）
```

同时确认：`AllowTcpForwarding` 未被改成 `no`（`sshd -T | grep -i allowtcpforwarding`），
云厂商安全组与服务器本机防火墙（firewalld/ufw/iptables）都已放行该端口。

#### 不想改 sshd 的方案

保持应用里「远端监听地址 = 127.0.0.1」，在服务器上装一个本机反代把公网端口转到
回环端口即可，例如 socat：

```bash
# 把公网 8787 转到隧道监听的 127.0.0.1:8787
socat TCP-LISTEN:8787,fork,reuseaddr TCP:127.0.0.1:8787
# 长期运行可写 systemd unit；nginx 则用 stream 模块做四层转发
```

socat 需要自行安装（`apt install socat` / `yum install socat`），并同样放行安全组。

#### 安全建议

- 优先用 `clientspecified` 而不是 `yes`（后者强制所有远端转发都绑所有网卡）。
- 为隧道单独建低权限 SSH 用户，配合 `PermitOpen 127.0.0.1:*` 限制可转发目标。
- `0.0.0.0` 意味着端口对公网开放，务必使用高强度访问密码（见上文密码策略）。


### 客户端配置

设置 → 移动访问 → 公网访问：

| 字段 | 说明 |
| --- | --- |
| 服务器地址 | 公网 IP 或域名 |
| SSH 端口 | 默认 22 |
| 用户名 | 服务器 SSH 账户 |
| 认证方式 | 私钥文件（推荐）或密码（AES-256-GCM 加密落盘） |
| 远端监听地址 | `127.0.0.1`（配合服务器反代）或 `0.0.0.0`（需 GatewayPorts） |
| 远端端口 | 服务器上映射的端口，默认 8787 |
| 自定义公网地址 | 可选；如 `https://guada.example.com`，留空则按「服务器地址:远端端口」推导 |

保存后隧道即时启停/重连，无需重启应用。设置页与弹窗会显示连接状态和最近错误：

> 隧道转发目标：生产模式为后端端口（编译产物），开发模式下为 Vite dev server
> 的 `127.0.0.1:5173`（热重载）。

- **已连接**：隧道建立成功，可扫码访问。
- **连接中**：正在握手/重连（断线自动指数退避重连，1s → 30s）。
- **连接失败**：常见原因包括服务器拒绝转发（`administratively prohibited`，检查
  GatewayPorts/AllowTcpForwarding）、私钥不可读、密码错误、端口被占用。

### 主机指纹（TOFU）

首次连接会记录服务器主机指纹，此后指纹变化将**拒绝连接**（防止中间人或服务器被
替换）。确认服务器确实重装/换机后，可在设置页「清除指纹」后重新连接。

## 移动端息屏/断网恢复

手机锁屏、切后台或网络切换后，SSE 长连接可能被系统半开（没有 FIN），浏览器不会
立刻报错。前端已内置连接监督，无需手动刷新：

- 页面恢复可见超过 15 秒、网络恢复（online）、bfcache 恢复（pageshow）时主动重建连接；
- 30 秒巡检：连接已关闭或超过 150 秒没有任何消息（后端每 90 秒心跳）时重建；
- token 过期导致握手 401（polyfill 放弃重试）时按退避重连，并触发一次鉴权校验：
  仍无效会回到登录页；
- 若息屏期间当前回合已经结束（服务端不再补发活跃流），重连后会核对会话状态，
  自动重新拉取当前会话历史，界面不会卡在“流式中”。

排查建议：解锁后若仍不更新，先在浏览器 Network 面板确认是否新建了
`/api/v1/events/sessions` 请求；若持续 401，重新登录即可。

## 已知限制

- 公网地址仅支持**根路径**部署；如通过 nginx 子路径转发，需自行改写资源路径。
- 尚未实现登录限速/防爆破；公网暴露时建议在服务器侧加 nginx 限流或仅开放可信来源。
- 多网卡（含虚拟网卡）会展示多个局域网地址，请选择手机实际可达的那个。
