# 主工作目录与附加工作目录统一操作接口设计方案

> 状态：已实施（Phase 1–3）。本文档是远程工作目录合并改造的基准设计文档。
>
> 2026-10-15 更新：附加工作目录新增第二种连接类型 **Docker 容器**（运行中的容器，agent 经
> `docker cp` 注入 + `docker exec -i --stdio` 管道通信；连接配置以 `kind` 判别，工具层与本文档
> 描述的 workspace 路由语义完全不变）。详见 [Docker 容器工作区方案](docker容器工作区方案.md)。

## 1. 背景与决策

项目采用**主工作目录 + 附加工作目录**模型：

- **主工作目录**：固定为本地目录。插件、记忆、todo、skills、git 面板等周边能力均强耦合本地文件系统，保持不变。
- **附加工作目录**：远程目标目录——**SSH 远程主机**或**运行中的 Docker 容器**——以连接为单位绑定到会话（会话附件 `ssh-connection`，存连接 ID，与连接类型无关），由目标端 `guada-agent`（Go）执行实际操作。

历史上远程操作走独立的 `remote_read/remote_write/remote_edit/remote_grep/remote_bash/remote_transfer` 六工具，与本地 file/shell 工具近乎完全重复，且输出格式已互相漂移（如本地 read 有 20KB 上限与 char 分页，remote_read 仅行分页）。

**决策：合并。** 保持主/附加目录概念不变，统一操作接口：标准文件与命令工具（read/glob/write/edit/grep/run_command/process）增加可选 `workspace` 参数，通过路由层分流本地/远程执行。`WorkspaceProvider` 抽象（`backend-ts/src/common/workspace/`）由此获得真实的远程实现。

## 2. workspace 参数语义

| 取值 | 含义 |
|---|---|
| 缺省 / `"main"` / `"local"` | 主工作目录（本地），工具走原有本地代码路径（零回归） |
| 其他字符串 | 附加工作目录的**连接名**（须精确匹配，且该连接已绑定当前会话） |

- 选择连接名而非 `ssh://` URI：与提示词连接清单一致、AI 直接抄写不易错、凭证不进 URI。URI 保留为内部表示。
- 远端路径权限由连接配置的 `perm` 三档控制（readonly / workspace / unrestricted），agent 端校验（含符号链接逃逸防护）。
- 会话 read-only 模式同时拦截远程写（与本地语义一致）。
- 远程访问一律经过 `RemoteAgentManager.getAgent` 的会话绑定校验——未绑定的连接无法操作。

## 3. 架构与数据流

```
AI 调用 read/glob/write/edit/grep/run_command (+ workspace 参数)
        │
        ▼
WorkspaceToolRouter（modules/remote-workspace/workspace-router.ts）
 ├─ 缺省/"main" → null → 工具本地分支（原代码不动）
 └─ 连接名 → RemoteAgentManager.getAgent（存在性+会话绑定校验+部署+缓存）
              → AgentWorkspaceProvider（agent-workspace-provider.ts，包装 RemoteAgent；SSH / Docker 共用）
        │  WebSocket JSON-RPC（SSH forwardOut 隧道，Bearer token 鉴权）
        ▼
远端 guada-agent（127.0.0.1 随机端口，断开即退出）
```

关键文件：

| 文件 | 职责 |
|---|---|
| `modules/remote-workspace/workspace-router.ts` | `resolveRemoteTarget(workspace, sessionId, attachments)` 分流；远程后台进程登记表；会话级远程进程收割 |
| `modules/remote-workspace/agent-workspace-provider.ts` | `WorkspaceProvider` 的 agent 后端实现（SSH / Docker 共用，`scheme` 由连接类型传入）：文件原语、glob（find+wc）、grep（--exclude-dir）、进程方法（`r:<连接名>:<pid>` 命名空间） |
| `modules/remote-workspace/remote-workspace-agent-manager.ts` | RemoteAgent 原语层（readFileRaw/writeFileRaw/stat/readdir/mkdir/unlink/rename/grepRaw/executeRaw/readFileRangeRaw/pollRaw/killRaw/writeStdinRaw/drainCompletedRaw）+ 会话级聚合收割 `drainSessionProcesses` |
| `modules/plugins/builtins/file.plugin.ts` | 五工具 `workspace` 参数 + 远程分支（read/glob/write/edit/grep） |
| `modules/shell/shell.plugin.ts` | run_command/process 远程分支 + TURN_STOPPING 远程收割与子代理远程进程检查 |
| `modules/remote-workspace/remote-workspace.plugin.ts` | ssh-connection 附件类型 + 连接清单 prompt + remote_transfer |

## 4. 各工具的远程语义对齐

- **read**：远程分支复用与本地完全相同的 `formatReadResult`（行/字符分页、`N\t|` 行号、20KB 截断续读提示）。非 UTF-8 编码经 base64 取回后 iconv 解码。
- **write / edit**：edit 采用 read → 变换（CRLF 归一 + 首次替换 + 行尾还原，`transformEdit` 本地远程共用）→ write，保证与本地语义一致（agent 的 replaceInFile 原语是"全部替换"，不用于编辑工具）。非 UTF-8 写入经 iconv 编码后走分块上传。工作区外写入的审批只作用于本地（远程由连接 perm 控制）；`sandbox_permissions` 提权参数已于 2026-10 移除。
- **glob**：agent 暂无 glob RPC，经 execute 原语执行 `find … -exec wc -c {} +`（静态前缀缩小起始目录、`-prune` 剪枝忽略目录、`-maxdepth` 对应 depth），Node 侧再做完整 glob 正则过滤（`**`/`*`/`?`、花括号展开）保证与 fast-glob 语义一致；不做行数统计（仅大小）。
- **grep**：经 execute 原语执行 `grep -rn[i] --exclude-dir=… -- pattern path | head -n N`。模式为 POSIX BRE（JS 正则的 `\d` 等不适用）；输出相对路径 `relPath:line: content`，无函数名上下文后缀。
- **run_command**：经 provider.execute，60s 前台超时转后台（agent 端语义，与本地 ProcessManager 对齐），转后台后输出写远端日志文件；输出清洗（StreamingSanitizer）与格式（`Latest output: --- … ---` + `[exit code: …]`）与本地对齐。RPC 兜底超时（命令超时+30s）失败时返回**可预测的远端日志路径**（`/tmp/guada-logs/<requestId>.out`），AI 可用 read 工具（带 workspace 参数）跟进。`background: true` 同样支持。
- **process**：远程进程 ID 格式 `r:<连接名>:<pid>`（多连接不冲突），kill/poll/write 按前缀路由到对应连接的 provider；轮询/终止/写 stdin 与本地工具同一入口。
- **turn.stopping 续跑钩子**：`drainRemoteProcesses(sessionId)` 聚合收割该会话所有附加连接上已完成的后台进程输出（格式同本地通知）；子代理额外快速轮询（≤1s/进程）登记的远程进程以判定"仍在运行"。
- **remote_transfer**：保留独立工具（语义为跨目录复制，本地对本地无意义），连接参数不变。

## 5. 提示词

- `file` 工具包 STATIC prompt：仅在会话绑定了远程连接时追加第 4 条——"附加远程工作目录已绑定，传 workspace=\"连接名\" 操作"。
- `ssh-tools` 工具包 prompt：连接清单 + workspace 参数用法（无绑定时机制性不注入，`loadMode` handler 返回 `none`）。
- run_command description 注明远程语义（POSIX sh、UTF-8 输出、r: 前缀进程）。

## 6. 兼容与回滚

- **历史会话渲染**：`plugins.controller` 的 `GET /plugins/tool-displays` 对 `remote_read/write/edit/grep/bash` 保留 legacy 展示映射（NLS 键仍在 `remote-workspace.lang.*.json`），持久化的旧工具调用块正常渲染。
- **本地回归风险**：本地分支代码路径未改动（路由返回 null 即走原代码），file/shell 插件既有测试全绿。
- **回滚**：恢复 `remote-workspace.plugin.ts` 中被裁剪的五个工具注册即可（工具实现已删除，需回退本次提交；legacy display 映射对已注册工具自动让位）。

## 7. 已知限制与后续方向

> 2026-09-05 更新：guada-agent v0.5.0 已补齐原生能力，下列 1/2/4 已销项（Node 侧保留旧版 agent 降级路径）。

1. ~~**agent 无 glob/readFileRange RPC**~~：**已解决**——v0.5.0 新增原生 `glob`（服务端模式匹配，`{files, hasMore}`）与 `readFileRange`（ReadAt + base64，钳制 1MB）RPC；Node 侧主路径走原生 RPC，旧版 agent（unknown method）自动降级 find 模拟/downloadChunk。
2. ~~**远程输出编码**~~：**已解决**——execute/poll/drainCompleted 支持 `outputBase64` 标志，agent 以 base64 携带原始字节，Node 按 `encoding`（iconv）解码，gbk 输出不失真；后台进程按 `r:` 前缀登记的编码解码（WorkspaceToolRouter 注册表）。
3. **周边能力未远程化**（按"主目录固定本地"语义刻意排除）：git 模块、前端文件浏览器（sessions.controller）、workspace-watcher、memory/todo/skills 落点、浏览器插件的文件读取。未来可经同一 `WorkspaceProvider` 抽象逐个接入。
4. ~~**grep BRE 语法限制**~~：**已解决**——agent 端 grep 重写为 Go regexp（RE2），`\d` 等常用语法生效，返回相对路径行；Node 侧旧版 agent 降级 shell grep（BRE）。
5. **连接以名字匹配**：改名会使已登记的远程后台进程 ID 失效；连接名创建时有重名校验。
6. **WorkspaceProviderResolver（common/workspace）**：目前仍只服务本地 fast path 的备用抽象入口；SSH/容器 provider 均未注册到 PluginRegistry 工厂（`registerWorkspaceProvider`）。统一后如需 `ssh://` 形态的 session.workspacePath，可在此挂接。
   > 2026-10-15：`SshWorkspaceProvider` 已更名为 `AgentWorkspaceProvider`（同时服务 SSH 与 Docker 两种连接，`scheme` 由连接类型传入）；Docker 连接经由 `RemoteAgentManager.connectDocker` 复用同一 provider 与路由，未走 Resolver。
7. **watch 事件推送未实现**（本次明确不做）：agent 端 fsnotify 注册无事件回路，provider.watch 为 no-op；workspace-watcher 远程接入留待后续。
8. **agent 后台进程输出架构重构**（v0.5.0，日志文件为唯一输出源）：修复输出捕获分叉（显式 background 曾只写日志、内存为空）、poll 快照竞态、stdin 管道阻塞 cmd.Wait 三个 bug 后，进一步删除内存缓冲——子进程 stdout/stderr 直接写 `<系统tmp>/guada-logs/<id>.out`（*os.File 继承 fd），poll/drain 按 readOffset **增量**返回"自上次以来的新输出"（对齐本地 ProcessManagerService，不再重复发送全量历史）；单次超限 10KB（对齐本地 POLL_MAX_OUTPUT_BYTES）head+tail 截断并置 `truncated`+`logFile`；内存占用恒定；日志生命周期不变（agent 不删，tmp 定期清理即回收）。Node 侧 provider/turn.stopping 透传 `truncated`+`logFilePath` 并在提示中指引用 read 工具读回。

## 9. 绑定提示词的"冻结快照 + 增量注入"（缓存稳定化）

**问题**：ssh-tools 提示词清单、工具列表（loadMode 门控）、file.plugin 第 4 条三处均随绑定实时变化，任一绑定变更都在下一回合打破 LLM 前缀缓存（系统提示词每回合重建）。

**方案**（两态状态机，`RemoteBindingStateService`）：
- `systemPromptIds`（冻结态）：系统提示词当前反映的绑定，仅冷启动（无记录初始化）与压缩后（MEMORY_COMPACTED）更新；
- `lastInjectedIds`（注入态）：绑定变更 → origin='system' 注入块**跟随下一条用户消息**（chat-runner.startStream 检测 → userMessage.injectedBlocks → addUserMessage 落库，复用沙盒叙事/命令标记同款管道），追加式不改前缀，KV 缓存零损失；
- ssh-tools 工具包改**恒 eager**：remote_transfer 常驻、提示词 piece 常驻（按冻结快照渲染，未绑定显示 none）→ 工具列表与提示词跨回合字节稳定；
- file.plugin 第 4 条改静态通用文案；
- 存储：SettingsStorage group `chat-session-state:<sessionId>`（独立 JSON 文件，避免前端整对象 PUT 覆盖 settings 内部字段）。

注入块文本含 "supersedes the connection list in the system prompt"，模型以最新注入为准；压缩后缓存本就重建，快照刷新让提示词反映最新绑定。
