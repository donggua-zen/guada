# 安全模式三档方案

> 版本：1.0 | 日期：2026-08-29 | 状态：已实施
> 前置：本文取代旧五值 `SessionRunMode`（normal/sandbox/memory/plan/free）。

> **Windows 用户可选档位（2026-10 起）**：Windows 后端不再向用户提供 `read-only`
> 会话档位——该平台没有可靠的 OS 级只读沙盒，shell 侧只是命令白名单，容易让用户
> 误以为存在系统级只读保证。输入区只展示 `workspace-write` / `danger-full-access`；
> 历史会话与旧客户端传入的 `read-only` 在创建、更新、读取、回合覆盖、子代理继承等
> 入口统一归一化为 `workspace-write`。**内部只读能力保留**：计划模式继续使用只读
> 命令策略，macOS/Linux 的三档语义不变。`/capabilities` 返回后端平台与可选档位，
> 前端据此渲染，避免 Web/移动端误用客户端平台判断。

## 1. 词表：三档，与 DSH `SandboxMode` 同构

| 模式 | 语义 | shell（run_command） | 文件工具（write/edit） |
|---|---|---|---|
| `read-only` | 只读（macOS/Linux 用户档位；Windows 仅计划模式内部使用） | Linux/macOS：经沙盒 `--read-only` 执行，全部写入被拒；**Windows：命令策略层**——**只读名单制**（默认拒绝）：只有名单里的命令放行，其余直接拒绝（不弹窗） | 直接拒绝（会话自己的记忆目录例外），提示用户切换模式 |
| `workspace-write`（默认） | 工作区可写 | Linux/macOS：经沙盒执行，仅工作目录内可写；**Windows：命令策略层**——**例外制**（默认执行）：只有必问项（出厂 26 条）、敏感路径、路径型动作越界、灾难级才拦（出厂规则随升级自动跟随，你的改动只记在 policy.yaml 的两个键里） | 工作区内或系统注册安全路径放行；工作区外**弹审批**（本次允许 / 放通此类·本项目 / 放通此类·全局 / 拒绝），无人可审批时拒绝 |
| `danger-full-access` | 自由编辑 | 不启用沙盒，也不做命令判定 | 不限制工作目录，可写任意路径（UI 红色警示） |

> **Windows 平台差异（2026-10 起）**：Windows 已停用 OS 沙盒（`sandbox.exe` 的受限令牌 + ACL
> 授权在该平台兼容性差：工作区授权失败、MSYS 工具崩溃、受限语言模式、junction/长路径不可用），
> shell 侧改由 `common/services/command-policy` 承担：用户两档各自单一语义（工作档 = 例外制；
> 只读档仅供计划模式内部使用），出厂规则是数据文件（不写进用户文件，随升级自动跟随），
> 用户文件只记"我的改动"+ 人工审批 + 无人值守 fail-closed。
> 文件工具采用同一审批模型（见 §2）。详见
> [windows-command-policy.md](windows-command-policy.md)。

- 词表只约束**文件效应**；网络与进程可见性不在词表内（："governs filesystem effects only"）。
- 默认值 `workspace-write`：新会话与未知持久化值均回退到该档。
- 持久化：`session.settings.sandboxMode`；子代理创建时从父会话继承（防权限逃逸）。
  Windows 上 `read-only` 在入口归一化为 `workspace-write`；计划模式的内部只读不经过该归一化。
- 模式切换叙事：用户消息 `metadata.sandboxMode` 记录当轮模式；`detectModeTransition` 比对
  上一条 user 消息，进入/退出 `read-only` 与进入/退出 `danger-full-access` 的叙事可叠加写入
  `metadata.systemReminder`。Windows 上历史 metadata 的 `read-only` 先归一化再比对，
  升级后首条消息不会误报"已退出只读"。

## 2. 能力放宽：只由用户授予（无模型提权）

**模型不能自我提权**——工具 schema 里没有 `sandbox_permissions` / `justification` 之类的提权参数
（2026-10 移除：避免模型用 justification 措辞误导用户，也让授权点唯一）。

- **命令（Windows）**：工作档走**例外制**——默认执行，只有必问项（可逐行删除）/ 路径型动作越界 /
  灾难级才拦，拦下来时弹审批卡（本次允许 / **放通此类·本项目** / **放通此类·全局** / 拒绝，
  「放通此类」把推导出的前缀规则写进 `policy.yaml` 的 `workspaceWrite.allow`）；只读档走**名单制**
  （内置只读名单物化在设置页可增删，名单外直接拒绝）；
  Linux/macOS 由 OS 沙盒拒绝越界，并提示用户切档。
- **文件写入**：`workspace-write` 档写工作区外（不含系统注册的安全路径）弹审批卡
  （本次允许 / 本会话内始终允许该路径 / 拒绝；审批记忆按解析后的绝对路径，大小写归一）；
  `read-only` 档直接拒绝（会话自己的记忆目录例外，见 §3）；`danger-full-access` 档放行。
- 两处审批都走统一 Ask（无超时），且**无人可应答时 fail-closed 拒绝**
  （子代理 / 机器人 / 界面无连接），绝不把回合挂在看不见的等待上。
- 档位切换只由用户在界面上完成；模型被拒后的正确动作是改用工作区内路径 / 只读命令，
  或回报用户请其切档。

## 3. 工具范围锁定与路径牢笼（原 memory 模式）

> **当前状态**：唯一生产调用方（压缩前影子轮次）已禁用（档位预设指向 `FAST`，见
> [memory.md](memory.md)），因此两个瞬态开关在运行期恒为 `null`——机制与测试保留休眠，
> 重新启用影子轮次后即生效。下文语义在启用状态下适用。

影子轮次（记忆同步）需要"只能碰记忆文件"的瞬态约束——这是**工具可见性**不是安全档位，
故与安全模式分离为两个瞬态开关（均不入库，`finally` 恢复）：

- `ISessionContext.setToolScope(pluginId | null)`：`MemorySyncService.runShadowTurn` 进入时
  `setToolScope("file")`（v1.5 起记忆由文件工具维护，不再有专用 memory 工具）；
- `ISessionContext.setPathJail(root | null)`：同一处 `setPathJail(memoryDir)`，把文件工具收窄到
  记忆目录内（`FilePlugin.resolvePath` 统一校验，覆盖读类工具）；
- `ToolExecutorService.executeTool` 对锁定范围外的工具返回 isError。

牢笼与安全档位的关系：**牢笼优先**。牢笼内的写入不受 `read-only` 限制（记忆维护是系统级写入，
原记忆工具同样绕过沙箱），牢笼外一律拒绝。前台（无牢笼）同样对会话自己的记忆目录开只读例外：
记忆是应用状态而非项目文件，前后台语义保持一致。牢笼还禁用远程工作目录参数，并在 glob 下拒绝
绝对 pattern 与含 `..` 的 pattern。详见 [memory.md](memory.md)。

## 4. 与 DSH 的对照

- DSH 词表同样是三档（`read-only` / `workspace-write` / `danger-full-access`），
  默认 `read-only`（fail-safe）；本项目默认取 `workspace-write`（工作区型助手的中档体验）。
- DSH 的 plan mode 是**正交的软引导协作状态**（prompt section + exit_plan_mode 工具），
  不读写沙盒与审批状态；本项目原 plan 把"协作状态"与"强制只读"耦合，属不规范来源，已移除。
- DSH 模式切换 = 追加 `sandbox/mode` log 事件（last-wins fold、replay 即状态、天然审计）；
  本项目暂存于可变 settings，后续如需审计轨迹可升级为同类 log 事件。

## 5. DSH 只读模式与命令行（问题确认）

- **只读可以调用命令行**`read-only` 只约束文件效应，命令照常执行；被拒写入以
  `sandbox.denied: true` 作为结果事实回报，并附提权引导（denial 是结果，不是工具不可用）。
  *本项目已于 2026-10 取消模型提权：越界改为"拒绝 + 提示用户切档"（见 §2）。*
- **终端实现**DSH 沙盒执行器有两套镜像实现，按部署挂载——
  POSIX 用 `dsh-bash-sandbox`（`bash -c <command>`，配 bwrap/Landlock/Seatbelt 后端）；
  Windows 用 `dsh-pwsh-sandbox`（`pwsh -NoLogo -NoProfile -NonInteractive -Command`，
  配 ACL restricted-token 后端）。工具 schema、结果分类、提权字段完全对偶（本项目已移除提权字段）。
- 本项目对应物：Linux/macOS 仍是自带 `sandbox.exe`（`--workspace cwd` + 可选 `--read-only`），
  二进制缺失时 fail-closed 报错，不静默放行；**Windows 已改为命令策略层**（`--read-only` → 只读
  白名单拒绝，可写档 → 审批弹窗），不再有 OS 级强制力，详见
  [windows-command-policy.md](windows-command-policy.md)。
